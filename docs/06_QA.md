### Update-Hinweis des Service Workers (Chromium, `tests/e2e/sw-update.spec.ts`)
Status: **geprüft (nur Chromium, ein Tab, lokaler Server)**. `scripts/build-update.mjs` baut Vorschau und öffentlich je als v1 und v2 (gleicher Quelltext, andere `CHUCCA_BUILD_ID`); `scripts/serve-update.mjs` liefert sie nacheinander vom selben Ursprung aus (`/__switch?to=v2`, nur mit `CHUCCA_ALLOW_SWITCH=1`). Eigene Konfiguration `playwright.update.config.ts`, weil der Server seinen Stand im Speicher hält (seriell).
- v1 installiert und steuert die Seite (`controller.scriptURL`, Caches `…assets-update-v1`, im öffentlichen Modus auch `…pages-update-v1`).
- v2 wird veröffentlicht, `registration.update()` bzw. eine neue Navigation: v2 installiert sich vorab (eigener Assets-Cache) und **wartet** (`waiting.state === 'installed'`); 1,5 s lang kein Reload, v1 steuert weiter, v1-Caches bleiben, Seite zeigt noch v1.
- Hinweis „Eine neue Version ist bereit.“ / „A new version is ready.“ / „Hay una versión nueva disponible.“ mit „Neu laden“ / „Reload“ / „Recargar“.
- Klick: genau ein Reload (Zähler im `sessionStorage`, nach 1,5 s Wartezeit unverändert), Seite zeigt v2, kein wartender Worker mehr, alle v1-Caches gelöscht, `assets-update-v2` vorhanden.
- Erstbesuch (kein Controller): `clients.claim` löst weder Hinweis noch Reload aus.
- Öffentlich: nach dem Update liegt HTML in `pages-update-v2`; Vorschau: nirgends HTML im Cache, kein `pages-…`-Cache.
- Eingaben: Vor dem Klick bleibt das Planer-Formular unberührt. Nach dem Reload füllt es sich aus dem Entwurf im `sessionStorage` wieder (Datum/Uhrzeit). Nicht belegt: andere Formulare (z. B. Anfrage auf „Besuch“) und nicht gespeicherte Eingaben ohne Entwurf – der Reload ist ein harter Neuladevorgang, sie gehen verloren.
- Gegenprobe: ein eingefügtes `skipWaiting()` im `install`-Ereignis lässt 6 der 7 Tests scheitern (Erstbesuch-Test prüft Controller-Wechsel ohne Vorgänger und bleibt grün).
- Grenzen: Safari/Firefox, mehrere Tabs (nicht getestet), echter Host mit CDN-Cache auf `sw.js` (`docs/11_HOSTING.md`: `sw.js` muss `no-cache` sein).
